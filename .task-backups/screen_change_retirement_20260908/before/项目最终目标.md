# 手机自动点击器项目最终目标（最高优先级）

确认日期：2026-08-11  
状态：用户已确认，作为项目产品方向和架构决策的最高优先级依据。

> 本文是项目最终目标的唯一权威入口。其他历史需求、交接文档、旧工作流或现有代码与本文冲突时，以本文为准。任何人不得在未取得用户明确同意的情况下，把项目重新缩减为微信、抖音或某一条命令的专用自动化。

> 当前风险边界同样由用户确认：只有登录/身份认证和付款/资金交易需要明确确认。输入、发送、提交、关注、评论、发布、收藏、删除、权限变更及其他普通操作均默认自动执行。未经用户批准不得新增风险类别或让这些任务重新等待确认；运行故障必须报告具体技术原因，不能伪装成产品风险。

## 1. 最终产品

本项目要实现一个可扩展到不同 App、不同自然语言表达和多台手机的通用视觉操作 Agent：

1. 用户在本机网页中用自然语言描述希望手机完成的目标。
2. 用户整段任务直接交给 Qwen；新会话从空动作历史和当前初始截图开始。不调用 DeepSeek，不生成固定子目标清单或隐藏计划。
3. Qwen结合整任务、本会话完整语义的实际动作/结果历史、摄像头中的本轮新截图（不传旧图），同次响应报告当前页面事实及最后动作的视觉结果，再给出一个 canonical 动作或整任务 `finish`。中间步骤完成不等于整任务完成。
   输入字段聚焦统一由同帧 `input_structure.application_inputs[*].focused=true/false/null` 表达；Qwen先综合本轮全部稳定帧独立认定输入事实，再依据目标选择动作，不从目标措辞倒推焦点。本地原样消费，不从可选光标措辞、键盘可见性、旧点击回执或本地视觉算法建立第二聚焦权威。只有绑定该字段的直接正向证据为true，只有另一字段已聚焦的直接证据为false，其余为null；闪烁光标可在任一稳定帧出现。未知或未聚焦时由Qwen选择聚焦点击并等待新截图；当前字段已空的清空结果式完成不要求聚焦。
4. 本地通用控制器只负责当前设备、当前观察、唯一 canonical 动作、坐标/机械可达和一次一动作等最小执行条件；除登录/身份认证和付款/资金交易外不增加产品门禁，也不负责写死某个 App 的业务流程。
5. 设备动作层默认通过机械臂完成点击、滑动、返回、长按和拖动；文字动作只使用用户批准的 ADB Keyboard（输入、清空、换行均为固定文字广播）。ADB Keyboard 只向当前已聚焦的 Android 编辑连接追加或清除已授权文字，不观察页面、不选择字段、不改变 canonical 动作；经用户批准的可选 `launch_app` 只可由本地可信注册表按包名启动 App。固定 ADB 可执行文件、固定设备 serial、固定 ADB Keyboard IME 和固定输入/清空广播只存在于本地 transport 内部，任何 ADB/Shell 参数均不向模型开放。
6. 每次设备动作后必须取得新截图；下一次 Qwen 结合整任务、实际历史和这张新截图选择一个动作或整任务 `finish`。`matched` 只证明刚才动作符合预期，不自动等于整任务完成；`finish` 直接陈述同一响应中的当前截图完成事实，不要求证据引用字符串；缺少单独 reason 时可使用同帧页面摘要。
7. 同一套循环必须能够扩展到新的 App。只要新目标能够由现有通用底层动作组合完成，就不应为该命令修改代码。
   输入/清空直接使用 Qwen 同帧选中的输入事实；本地执行编号不要求模型生成或跨结构重复。完成事实直接表达，不要求模型编写元素/字段路径。简化不改变当前新图、实际效果防重复、设备与机械标定边界。
8. 架构从现在开始携带 `device_id` 和独立任务状态，为以后同时调度多台手机保留统一接口。

## 2. 唯一执行循环

2026-09-05 用户明确选择：删除人为任务/正文/字段/收件人容量及上下文截断，保留真实资源错误；图像检查先验证误拦样本；局部重试次数改整任务可配置累计预算，允许新图纠正而不重放不确定效果；文字只使用ADB Keyboard并删除机械键盘/OCR/拼音候选执行；删除额外手势距离/边缘比例限制；删除元素数量和标题/分页等固定表达要求。2026-09-08 用户根据动态画面离线反例批准删除动作前整图差异、机械执行前整图亮度/结构差两道否决，接受模型思考期间真实跳页或目标移动可能导致一次错点的取舍。保留当前截图、稳定/清晰度、尺寸、设备/scope/一次性凭据、机械范围与动作后输入/效果保护，不新增替代视觉裁决。以上为产品方向，代码落实及未完成项只以交接和验收台账记录，不由本段推导已完成。

```text
用户自然语言目标
  ↓
Qwen：接收原任务、本会话实际动作历史和新截图
  ↓
Qwen：同一次响应发布当前画面并选择一个动作或 finish
  ↓
通用控制器：检查当前动作能否唯一、有效地执行
  ↓
设备动作层：执行一个 canonical 动作（机械臂动作、可信 ADB Keyboard 文字动作或批准的可信包名直启）
  ↓
重新拍摄并再次交给 Qwen
  ├─ action：精确映射后只执行一次
  ├─ finish：以当前截图和本会话历史判断整任务完成
  ├─ 本地技术故障：报告设备、观察、映射或机械原因并停止，不伪装成Qwen语义结论
  ├─ 普通外部状态动作：按用户目标自动执行并验证结果
  ├─ 登录或付款：展示具体对象与内容并等待确认
  └─ 目标完成：保存可见证据并结束
```

循环本身可以固定，但用户目标、任务步骤、App和页面路径不能写死。

用户于2026-09-06批准单视觉模型整任务循环，替代此前薄顺序方案。删除 DeepSeek 首次计划、固定子目标及本地按预先清单核对完成的权威。整任务语义是否完成由 Qwen 判断，用户接受可能漏步骤或误报完成的模型风险；本地不声称独立证明无遗漏，也不悄悄恢复隐藏计划。设备、新图、一次执行、正文结果、累计预算和不确定效果不重试仍保留。
2026-09-07用户明确批准唯一有限例外：选择 open_recent_apps 后由本地导航状态负责“非主屏幕先 Home → 新图确认 Launcher → 打开后台 → 新图交回 Qwen”，已在 Launcher 时直接打开。此规则适用于所有打开后台动作，不扫描任务关键词；导航未完成时不能由其他动作或 finish 跳过。只消费当前视觉身份，每步新图/新 scope、共用任务预算，暂停保留进度；原始模型建议和本地执行来源分别记录。下文“本地不重新选择动作、Qwen选择下一步”的一般职责均以此明确例外为限，不扩展到输入、发送或本地整任务完成判断。

## 3. 模型与本地控制器的职责

### 已退役的规划职责

DeepSeek 不在正式运行路径、启动依赖或 doctor 就绪条件中。不得以兼容层、备用计划或隐式子目标恢复第二套动作/完成权威。

### Qwen

- 读取摄像头中的真实手机画面。
- 结合整任务和本次历史识别页面、文字、图标、输入框、键盘、弹层和元素状态。
- 每轮只给出一个下一 canonical 动作或整任务 `finish`；普通页面/容器滚动直接绑定同一响应中的方向，直接操纵目标元素的滑动绑定同帧元素引用与起终点轨迹，当前画面确实无法形成唯一动作时由本地报告具体观察故障，不再让模型发布第三种普通语义终态。
- 打开后台的导航顺序由上述本地例外负责；导航后 Qwen 以新截图判断 `screen_id=system_recent_tasks`。清理全部后台或指定后台 App 时，只选择当前截图中唯一可见的系统“一键清理全部”按钮并执行一次 `tap_semantic`；用户允许同时清除其他可清理后台。按钮不可见时按新图 scroll 寻找，不猜点、不用 swipe_element 移除卡片。清理按钮规则不扩展到普通查看/切换，不建立 App、截图或固定坐标流程。
- 不直接调用机械臂；其建议必须经过本地控制器检查。

### 本地通用控制器

- 保证同一时刻只执行一个动作，且使用确认前重新观察的新画面。
- 将视觉坐标转换为经过标定的机械臂坐标。
- 检查模型所选动作是否精确绑定同一响应中的当前目标、当前画面可用性和动作边界，并仅按本地唯一政策识别登录或付款确认；点按类动作只接受 Qwen 同帧严格 `decision.target`（无 bounds/box/states/其它几何）与唯一 `tap_point`，该分支提示模型将 `scene.elements` 留空，若附带则在入口排除，仅保留原始诊断，不参与执行或否决。本地只校验目标身份、坐标范围与机械标定，typed 输入辅助动作再与同帧 input_structure 投影身份一致；不得从粗 `bounds` 中心推导，也不得用 OCR、颜色/表面分割或其它视觉算法改写落点、构造第二候选或新增否决权。无关可选字段和重复摘要不得否决任务。
- 本地会话层只负责用户批准的 open_recent_apps 导航顺序，Controller/设备层仍只执行本次动作。后台清理按钮由 Qwen 选择，不用卡片滑动清理；不得仅凭 system_recent_tasks 页名禁止普通浏览/切换的横向 scroll 或非清理元素手势，不建立本地清理意图识别。
- 不编排“抖音点赞流程”“微信加好友流程”等业务脚本。
- 动作后的 App 身份和导航栏是否显露由 Qwen 根据新图决定继续或完成，本地不再以包名/标题匹配或 navigation_bar_visible 字段建立第二套后置裁决；可信包名执行、动作前几何、设备/新图/正文与效果防重复不变。

### 设备动作层

- 只提供通用底层动作：点击、页面/容器四向滚动、目标元素轨迹滑动、返回、长按、拖动、等待、文字输入/清除，以及用户批准的可选可信包名直启 App。
- 包名直启只接受本地注册表签发的 opaque target，不接受模型或用户提供包名、组件、Intent、ADB 参数或命令；不可用时继续使用当前画面上的 App 图标。
- App 内的目标定位、字段身份、动作选择和结果验证始终使用相机、当前截图、canonical 与本地控制器；点击等导航动作继续由机械臂完成。ADB Keyboard 只能作为设备已显式配置的可信文字 transport，消费同一 `input_verified_text` / `clear_verified_text`，不得读取页面、寻找字段、形成第二套输入权威，也不得失败后自动回退重输。
- 不得扩展为任意 ADB 输入或 Shell、卖家文字对话框、剪贴板、Accessibility 节点树、force-stop、清数据或后台脚本；唯一允许的 ADB Keyboard 命令族为固定 IME 状态核对和固定 `ADB_INPUT_B64` / `ADB_CLEAR_TEXT` 广播，并且必须绑定本地可信设备配置。
- 动作层不知道“关注”“聊天”“拉群”等业务含义；用户原任务限定目标，Qwen依据每张当前截图决定动作或完成，动作层只执行 canonical 动作。

## 4. 不得退化的红线

以下做法均视为偏离最终目标：

- 每出现一种用户说法就增加一个命令、正则表达式或接口。
- 为微信、抖音或某一页面继续堆独立的线性状态机，并把它当成产品主路径。
- 用“单次点赞成功”“单次上划成功”代替通用 Agent 已完成的证明。
- 因为当前测试场景是某个 App，就把通用协议改造成包含该 App 名称的流程协议。
- Qwen识别失败后不断增加针对某张截图的坐标补丁或视觉特判。
- 动作执行后不重新观察，仅以机械臂命令已发送判断成功。
- 为了追求“任意操作”而允许模型输出未经校验的裸坐标、连续自由动作或系统命令。

App专用知识只能作为可选视觉提示、语义别名、用户批准的可信包名映射、安全规则和测试样本，不能成为任务编排核心。

## 5. 开发决策检查

开始任何功能前必须回答：

1. 这项修改增加的是通用能力，还是只让一条固定命令通过？
2. 换一个 App 或换一种说法时，这项能力是否仍然可复用？
3. 新命令如果只由现有动作组合而成，是否可以不改代码直接执行？
4. 动作后是否有真实画面证据验证结果？
5. 是否破坏Qwen整任务视觉动作、本地控制器校验、机械臂执行的职责边界？

如果答案表明它正在形成单功能闭环，应立即停止实现，向用户说明偏离点并先调整架构。

## 6. 分阶段交付

1. **整任务上下文**：原任务、本会话实际动作历史和新截图只进入一个 Qwen 循环；没有固定子目标或本地完成清单。
2. **唯一动作协议**：Qwen 在同一次当前截图响应中直接给出一个 canonical 动作或 `finish`；本地只校验动作类型、当前元素绑定、scope/fingerprint、合法几何和可信 transport，不再生成第二份 canonical catalog、候选排名或语义否决。
3. **通用动作执行**：机械臂稳定执行点击、滑动、返回、长按和拖动；文字仅由 ADB Keyboard 执行同一 canonical 输入、清空及换行动作；可选直启只执行一个本地可信包名动作。
4. **连续单循环**：每次动作后取得新截图，由下一次 Qwen 响应决定继续一个动作、报告整任务完成；异常由本地照实停止。
5. **通用网页控制台**：一个自然语言入口、当前动作及实际历史、实时画面、执行轨迹、停止和风险确认。
6. **跨App陌生命令验收**：在没有预编排命令的情况下，通过已有动作组合完成多个 App 的新目标。
7. **多手机调度**：每台设备独立标定、队列、状态和锁，不同设备可并行，同一设备只能有一个物理控制任务。

## 7. 最终验收标准

项目不能以某个固定流程成功作为最终验收。至少需要证明：

- 用户输入项目中未预设过的自然语言命令，系统能结合当前画面逐步执行。
- 同一目标换一种说法，仍能生成等价目标并完成任务。
- 系统能在至少三个不同 App 中组合执行多步任务，而不为每条命令新增代码。
- 起始页面、弹层或页面路径发生变化时，系统会依据新画面调整，而不是继续执行固定序列。
- 文字输入、导航、选择、普通发送自动执行和结果验证能够进入同一个通用闭环；登录、付款在执行前确认。
- 代码测试、模型离线测试和真实设备验证分开记录；最终成功必须有动作后真实画面证据，机械动作另须保留物理回执。
- 多手机版本能按 `device_id` 隔离状态、标定和任务，并防止同一设备被两个任务同时控制。

## 8. 当前任务的优先级

当前最优先工作不是继续优化某一次点赞或某一条客户寻找流程，而是把以下主路径真正变成默认运行方式：

```text
通用自然语言目标
→ Qwen接收原任务及本会话实际执行历史
→ Qwen依据当前新截图选择一个 canonical 动作或 finish
→ 通用设备动作（默认机械臂；文字唯一 ADB Keyboard；可选可信包名直启）
→ 重新截图并再次交给 Qwen
→ 当前截图 action/finish 串行推进
```

旧微信、旧抖音固定工作流已从正式服务退役：不得注册 API、初始化运行时、参与规划或拥有否决权。历史源码和隔离测试只能用于追溯，通用能力必须位于通用模块。
