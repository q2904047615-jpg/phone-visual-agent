## 5. 同类问题样本与根因

本阶段不是修复某张截图，而是处理同一架构根因：历史演进把同一串行闭环拆成大量重复投影、重复校验和
内部专用协议，造成维护成本远高于动作本身。

- `universal_agent_orchestrator.py`：多个生命周期入口重复组装同一步状态、证据和错误终态。
- `generic_scene_observer.py`：一个远程响应在多个输入/几何/键盘分支重复解析、规范化和否决。
- `task_graph.py` + `task_semantic_ir.py`：模型 wire、领域状态、风险预览和兼容规范化混在两套大型对象图中。
- `canonical_action_protocol.py` + `universal_action_controller.py` + `generic_action_adapter.py`：同一动作的目录、
  参数、前置、执行和后置规则散落并重复枚举。
- 输入、能力验收和诊断模块仍有历史专用包装；只能在主链替换稳定后按真实调用图继续收敛。

## 9. 正式运行调用图与替换顺序

正式 Web 组合根只装配一条链：

`web_app -> UniversalAgentSessions -> UniversalAgentOrchestrator`

Orchestrator 的正式依赖为：

`DeepSeekTaskGraphPlanner -> DynamicTaskGraph/TaskSemanticIR -> ObservationBridge ->`
`SingleStepGenericSceneObserver -> QwenVisualDecisionObserver -> CanonicalActionCatalog ->`
`GenericSingleActionAdapter -> UniversalActionController -> DeviceExecutor -> RobotController`

动作后由 Adapter 取得新帧，Controller 只验证刚执行的 typed transition；Orchestrator 再让 DeepSeek 推进或
重规划。文件系统证据、输入 lineage、相机协调、方向凭据和设备独占是这条链的注入端口，不拥有任务、
视觉或动作第二权威。

替换顺序固定为：

1. `task_graph.py + task_semantic_ir.py + deepseek_task_graph.py`：把模型 wire、领域状态和两类风险收敛成一套；
2. `generic_scene_observer.py + qwen_visual_decision.py`：每张当前截图只形成一份 typed scene；
3. `canonical_action_protocol.py + universal_action_controller.py + generic_action_adapter.py`：同一动作规格表驱动
   候选、参数、前置、执行和后置；
4. `universal_agent_orchestrator.py`：只保留串行生命周期、一次确认、一次纠正、证据和 DeepSeek 推进；
5. 输入、能力验收与硬件基础设施按新主链真实需要收敛。
