# 手机自动点击器项目规则

请尽可能以最低的成本和时间完成项目，同时以真实证据和通用能力为准，不用堆叠流程换取表面稳定。

## 审查诚实性与防止重复违背用户决定

- 阅读范围必须如实说明：局部阅读、关键词搜索、历史总结和测试通过均不等于完整审查。没有完成当前版本的全项目审查，不得声称“已看过全部代码”“整体没有冲突”或“任务一定能完成”。
- 用户要求审查整个项目时，先列出项目自有源码、配置、提示词、测试及有效文档的范围，记录当前版本与未提交修改，逐项标记已完整读取、仅搜索、未读及排除理由。依赖、生成物、二进制和历史证据可分类排除，但不得悄悄排除相关入口；清单未完成前不得宣布全项目审查完成。版本变化后须重新核对受影响部分。
- 对整体架构、反复失败或跨模块冲突给出根因及修改方案前，必须沿真实入口读通相关完整运行链，包括实际启用的配置、模型请求构造、解析绑定、执行、结果回写、失败与成功终态，以及可能冲突的旧入口。明确证据支持到哪一层；链路未查清时只报告局部事实和待查项，不边猜边修改。
- 提出方案前先核对用户最新明确决定、项目最终目标和用户决策与协议边界。用户要求删除或退役的机制不得以“补漏”“验证”“轻量版”等名称默认加回；若确有必要建议恢复，必须明确说明是在改变既定架构、与旧机制的实质关系及替代方案，未经新的明确批准不得实施。
- 修改前说明具体位置、影响范围、验证方法和尚不确定之处。只有实质歧义会改变结果或授权范围时才询问；已经明确的决定不反复要求用户重说。发现建议违反已确认决定时，立即撤回建议并停止相关改动，先核查冲突来源。
- 汇报严格区分已阅读、已实现、测试通过、已加载、真实单步结果和完整任务完成。验证脚本本身也须核对输入时序及证据来源；模型响应合法、执行回执成功或局部样本通过不能替代任务完成证据。出现反例必须保留并明确推翻相应结论，不继续沿用旧的成功口径。

## 项目目标与唯一权威

- 开始任何设计、修改或测试前，必须完整读取根目录 `项目最终目标.md`；它是产品方向与架构决策的唯一最高权威。
- 本项目是可扩展到不同 App、不同自然语言表达和多台手机的通用视觉操作 Agent，不得退化为微信、抖音、点赞、评论、客户寻找或任何固定命令的专用脚本。
- 新命令能由现有通用底层动作组合完成时，必须无需修改代码即可执行。主要增加 App 名称分支、固定命令、固定步骤、截图坐标补丁或单功能状态机的方案，必须停止并先向用户说明其不具通用性的原因。
- App 专用内容只能作为视觉提示、语义别名、用户批准的可信包名映射、安全策略和测试样本，不能承担任务编排。
- 同一时间只有一个任务可以控制当前真实设备的机械臂或 ADB Keyboard 文字 transport；其他任务只能进行文档、代码、离线截图和自动测试。

## 产品边界与正式运行权威

- 用户已要求屏幕变化不能作为错误：视频、动画和跨帧像素差异不得在观察、动作前后、doctor 或卖家鼠标回执层否决任务。像素变化仅可记录诊断；不得恢复 PX/MM 背景像素稳定/往返确认或动作后取景差异门。机械回执只表示事件已派发，不能声称卖家已处理或手机触达。保留截图尺寸/清晰度、设备、scope、一次性授权、机械几何、当前输入结果和不确定效果不重放。

- 当前唯一需要明确确认的产品风险是 `authentication`（登录/身份认证）和 `financial_transaction`（付款/资金交易）。
- 输入、发送、提交、关注、评论、发布、收藏、删除、权限变更、打开 App、点击、滑动、长按、拖动、返回和 Home 均默认自动执行，不得仅因改变账号、内容、数据或外部状态而要求确认。
- 设备断线、控制权缺失、画面不可用、目标完全无法识别和机械坐标不可达是运行故障，不是产品风险；必须报告具体技术原因。
- 未经用户批准，不得新增风险类别、敏感词、动作词黑名单、App/目标限制、人工确认、失败关闭，或其他会让合法任务变成 `blocked`、`confirmation_required`、`unsupported` 的边界。
- 所有会改变产品能力的边界必须先更新根目录 `用户决策与协议边界.md`，并在回复中明确告知用户；禁止只改代码、不告知用户。
- 同一类判断只能有一套正式权威。新协议启用时必须删除旧运行时入口、旧否决权、旧正则和旧默认值；历史协议只能作为只读证据或显式隔离测试。
- 用户批准的单视觉整任务循环：Qwen 接收原任务、本会话实际动作/结果历史和当前新截图，同次响应给一个 canonical 动作或整任务 finish。新会话历史为空，历史只含已执行事实并保留完整 canonical 动作语义；2026-09-14 用户将此前只传新图的选择更新为：每次 action/finish 判断都发送本任务保存的全部截图，按采集顺序标明 HISTORY/CURRENT，包括动作前后与重新观察帧；不采样、不覆盖、不截断，不混入其他任务或设备，资源错误如实报告。当前新图仍是字段、坐标和 scope 的唯一权威。DeepSeek 初始计划、固定子目标及按预先效果清单核对完成均退役，不保留隐藏计划或兼容双权威；用户已接受语义遗漏/误报完成不能由本地清单独立证明的取舍。当前正文结果、设备/截图/scope/机械及不确定效果不自动重试保持。

- Qwen 不拥有普通语义 `blocked` 否决权。Controller 只处理当前设备、scope、几何和一次执行结果；本地 selector、动作后 DeepSeek replan、可见进度和 App lineage 不得建立第二套动作或完成权威。
- Controller不得恢复launch_app后的包名/App名称/标题视觉匹配或reveal_system_navigation后的导航栏可见字段硬拒绝。新截图的Qwen action/finish直接交给既有唯一绑定及顺序执行链；matched不等于业务目标完成。可信launch配置、动作前导航几何、当前观察/设备/正文和效果保护仍保留。

- 单步模型响应使用扁平 nullable schema，不依赖 oneOf/anyOf 条件分支；不适用于当前动作的字段为 null，组合合法性仍由唯一 canonical 解析器检查。点按分支跳过 compact scene 的元素枚举/bounds/states 要求；这些元素规则只适用于非点按动作或 finish，禁止再次引入与 decision.target 冲突的目标框要求。
- `matched` 只证明刚才动作符合预期；只有当前新截图响应中的 Qwen `finish` 才能结束整任务；有后续要求时继续 action，不能把中间动作完成当成整任务 finish。
- `tap_semantic`、`dismiss_overlay`、`double_tap`、`long_press` 的唯一目标身份是 Qwen 同帧严格 `decision.target`，其字段只允许 `role/meaning（label/evidence为可选说明；element_id若附带只作诊断）`；该点按分支提示模型将 `scene.elements` 留空；若附带则在唯一观察入口、任何元素校验/引用绑定/输入判断之前排除，仅保留原始响应诊断，不参与执行或否决。非点按及 finish 的元素事实不变；target 禁止 bounds/box/states/其它几何，唯一点击落点为同帧 `tap_point`。Controller 只校验目标身份、tap_point 数值/屏幕范围、scope/fingerprint 与机械标定；typed 输入辅助动作还必须与同帧 input_structure 的本地投影身份一致。正式运行不得从元素 `bounds` 中心推导落点，也不得以 OCR、颜色分割、局部表面检测或其它本地视觉算法改写该点、生成第二候选或新增否决权；动作后效果只由新截图中的 Qwen 判断。
- `swipe_element` 的起点必须属于当前目标元素，终点必须在屏幕内，轨迹必须有限、非零且具有唯一主方向。不得恢复2%边缘、8%最短/90%最长距离和比例内缩限制；真实机械标定与硬件包络保留。导航、聚焦、滑动纠正使用同一整任务累计预算，不再用聚焦一次、元素滑动两次等局部次数否决；每次重新取图并签发新scope，不能重放旧坐标凭据或重复不确定效果。预算用尽保留进度并暂停，不得记成功或按请求刷新计数。
- 当前输入预编辑只由同帧`input_structure.application_inputs[*].preedit_text`报告，与已提交正文`text`分开；无可见预编辑为空字符串。本地不从键盘模式、候选字、光标措辞或拼音推导，不再接收旧键盘/候选几何作为执行权威。`press_enter`绑定当前已聚焦的typed多行字段，通过固定ADB文字广播追加一个换行，不选择Enter按键，不要求target/tap_point，也不新增ADB keyevent。
- 当前输入正文的唯一视觉权威是同一单步响应中的 `input_structure.application_inputs[*].text`。scene 输入元素只是可选页面上下文，不得被要求与 `input_structure` 重复存在、重复正文或达到几何重合阈值，也不得因 `states.value`、文字、占位符、光标、标签、证据或其它可选视觉事实缺失而生成、覆盖或否决正文。同帧选中的当前字段已唯一确定时，唯一合法 bounds 的空字符串字段可以成立；聚焦前唯一可界定的完整编辑栏中心空白面可以签发聚焦点击；纠正依据新图并受整任务预算约束。
- 输入/清空不要求 Qwen 声明或猜测本地元素编号。Qwen 在同帧 input_structure 中报告当前选中输入框，唯一投影生成内部身份；scene 的重复输入元素不进入执行，正文、聚焦和完整边界只取当前输入事实。模型输入编号与完成 evidence_refs 若附带只留原始诊断，不形成引用绑定或否决；finish 直接消费同帧 reason 或页面摘要的完成事实，仍保留当前输入结果、本次动作与新图、设备和 scope 检查。禁止恢复输入编号交叉裁决、scene 粗输入面回退或证据路径解析。
- 当前观察的设备动作集合一次签发，模型、canonical 和执行消费同一不可变集合，响应后不再次裁剪。聚焦只看同帧输入结构，不要求先有点击回执。字段已聚焦可直接输入/清空；当前正文和预编辑均空时无需空清空。是否整任务完成仍由 Qwen 根据新图和本次历史判断，不能恢复本地子目标完成裁决。
- 当前同帧聚焦唯一事实为 `input_structure.application_inputs[*].focused`（true/false/null）。Qwen须先综合本轮全部连续帧独立认定输入事实，再选择动作；不得从任务措辞或想选的动作倒推焦点。仅有与该字段绑定的直接正向视觉证据时为true；仅有另一字段已聚焦的直接证据时为false；其余为null。闪烁光标可出现于任一连续帧，单帧未出现不等于false。本地仅类型规范化和原样投影，不凭键盘可见、光标关键词、scene.focused、历史点击或本地视觉检测补成true。false/null不影响字段正文、导航、聚焦或空清空finish；非空文字动作只绑定同帧focused=true的目标字段。不得恢复旧焦点推导函数或运行时兼容。
- Qwen 输出的 scene/element/decision `confidence` 只作诊断，不得成为普通动作候选、canonical 映射或动作后验证的第二否决权。独立本地方向凭据、真实帧清晰度、合法坐标、唯一候选、设备与 scope/fingerprint 校验继续保留。
- 用户于 2026-09-02 批准的 ADB Keyboard 是正式运行中唯一的文字 transport，仅执行本地可信设备配置签发的固定 `ADB_INPUT_B64` / `ADB_CLEAR_TEXT` 广播；它不观察页面、不选择字段，也不形成第二套视觉、字段或动作权威。机械文字输入、拼音分段/候选选择和键盘OCR全部删除，不保留机械回退。Visual Agent Companion IME 及其 bridge、配对和 editor session 全部退役，不得保留运行时兼容或回退入口。
- 用户批准的 `launch_app` 只可使用本地可信包名注册表。ADB Keyboard 与 `launch_app` 均不得扩展为任意 ADB/Shell、卖家文字对话框、剪贴板、Accessibility、force-stop、清数据或后台脚本；ADB Keyboard 只允许固定可执行文件、固定设备 serial、固定 IME 和上述固定广播命令族，任何参数均不得来自 Qwen 或网页。

## API 与运行环境

- 用户已授权：每个代码修改批次完成并通过相应验证后，Agent 自行重载本工作树项目 API 并核对加载版本、官方客户端 status/doctor，不再另行询问“是否加载”。同一批次不按每个小改动重复重载；纯文档修改不重载。重载前确认无正在执行的设备任务，不中断其他任务；只重载项目 API，不操作卖家 main.exe。加载授权不自动授权新增手机任务、远程模型采样、提交或推送；环境故障如实报告，不把未加载或未就绪说成成功。
- 调用项目 API 前，必须从当前源码路由声明或当前服务 `/openapi.json` 核对 HTTP 方法、完整路径和请求 schema；禁止按 REST 习惯猜测端点。
- 没有公开列表端点时，只能使用公开状态字段或已知 `session_id`，不得用猜测路径探测服务。
- 路径、方法或请求体错误导致的 `404`、`405`、`422` 是 Agent 命令错误，不得归因于项目协议、模型、设备或手机状态；服务或路由变化后必须重新核对。
- 项目命令行和 Agent 调用必须使用 `poc/local_agent_api_client.py` 或 `poc/agent_api_cli.py`，禁止手写 `Invoke-RestMethod`、`curl` 或拼接通用 Agent URL。
- Agent 重载项目 API 时，必须在能枚举卖家控制窗口的同一交互式桌面权限上下文中启动。重载后用官方类型化客户端确认 `controller_online`、`camera_online`、Qwen 配置和活动任务；需要画面时还要确认网页取得真实相机预览。
- 真实控制器模式下的 `MOCK PHONE` 是相机捕获失败占位，不是预览成功。若重载前设备在线而重载后离线，先核对启动权限上下文；只重载项目 API，绝不操作卖家 `main.exe`。

## 当前架构方向

- 代码组织采用轻量、渐进式 DDD 模块化单体，不拆微服务，也不一次性重写。
- 新模块依赖方向固定为 `interfaces -> application -> domain`；`infrastructure` 实现 application/domain 声明的端口并由组合根注入。domain 不导入 FastAPI、Pydantic、Web、模型 SDK、摄像头或机械臂实现，application 不导入 interfaces 或 infrastructure。
- 每个迁移批次只搬一个真实运行的业务切片。新入口接管后必须删除旧调用和旧状态权威，不得用 facade、兼容开关或双写保留两套生命周期或动作判断。
- DDD 只划分职责和依赖，不得改变 canonical 动作权威、串行截图闭环、模型调用次数、公开 API、风险边界或机械执行语义。未迁移模块继续作为正式实现，不得仅靠目录名称包装成虚假领域层。

- 读取交接文档明确指向的一个当前验收台账，且默认只读标题为“本轮唯一能力缺口”“尚未完成的证据”“下一决定性动作与停止条件”的三段。历史批次、旧会话、整批输出和已完成阶段证据仅在追溯对应问题时按需读取，不得作为默认上下文。

## 新失败与方案预检

- 每个失败只归入一个主要类别：代码缺陷、模型随机/合同输出、环境或服务状态、手机起始状态、验收设计错误、文档口径错误。
- 能离线复现的失败先保存最小输入并离线复现；不能复现时先只读观测，不凭猜测改代码。只有证实为通用实现缺陷时才修改生产代码。
- 通用手机视觉动作出现任何新错误或失败时，修改生产代码前必须核对 Open-AutoGLM 官方仓库（`https://github.com/zai-org/Open-AutoGLM`）当前实现及相关 issue。只借鉴跨 App 机制，不复制 App、截图、固定坐标或单任务补丁。
- 核对后先向用户说明：本项目真实根因、Open-AutoGLM 的处理方法、两者适配差异、所有已识别的实质疑点和失败路径、最小验证办法、影响范围与回滚方式。官方没有可复用解法时，基于本项目证据提出候选方案。用户同意后才能修改生产代码。
- 架构、协议或产品边界变化还必须遵守全局 `AGENTS.md` 的实施前反证规则。普通局部缺陷只需最小复现、通用修复和相关测试，不得用文档流程延迟基础功能。
- 不得因单张截图、某个 App 路径、固定坐标、单次模型输出或单一枚举措辞追加生产特例；新增同义词或动作映射必须形成跨 App 的正式等价语义。

## 实施与验证收敛

- 一个修复批次按以下顺序完成：汇总同根因失败样本；设计一个通用修复；一次性修改；重放全部历史失败样本；运行最小相关测试；批次稳定后运行一次相关回归；准备提交或真机验收时才运行一次完整回归；离线证据通过后只做一次最终真机验收。
- 验证必须含正向样本和至少一个变化样本（换措辞、换画面状态或换 App 中适用的一项）。只让原失败样本通过不能证明通用修复。
- 禁止把真机当调试器，禁止每个小改动后重复完整回归或重启服务。文档-only 修改只做格式、链接、差异和一致性检查。
- 离线测试失败时不得启动、停止、重启或刷新卖家 `main.exe`；服务只做只读核对。日志与接口结果优先提取关键字段，原始证据保留在文件中。
- 只有新增产品边界、改变正式协议权威或架构级修改，才需要落盘验收缺口与根因、同类失败样本、通用修复说明和验证清单；普通缺陷不得因此停顿。

## 模型合同与停止条件

- Qwen 输出由本地确定性解析器与类型/风险校验器裁决，模型不得扩大权限。仅当修复结果唯一、只修语法且不改变语义时，允许一次本地有界规范化；禁止通过多轮远程调用抽取合法答案。
- 只有缺失信息导致目标、动作或当前设备无法唯一执行时才停止；无关可选字段、自然语言变化、旧枚举或重复非权威检查不得阻止合法任务。过期 scope、错误设备、目标完全无法识别和机械不可达按运行故障停止。
- 同类模型合同失败连续两次，停止继续采样或微调提示词，回到接口合同与解析边界；同一根因修改两轮仍未缩小验收缺口，停止扩展补丁并重新审查根因、验收合同和最小复现。

## 真机执行

- 真机动作前重新核对 `/api/device`、controller、camera、busy、选中 `device_id`、活动会话、最新 observation/fingerprint 和卖家 `main.exe` PID。
- 不得启动、停止或重启卖家 `main.exe`，不得点击卖家全屏、横屏、竖屏或底栏。
- 一次只执行一个设备动作。动作前取得新观察并记录当前可见状态、唯一动作、预期后置条件和失败停止条件；动作后重新观察，只按新证据继续。
- 普通只读或导航动作无预期变化时，在整任务预算内取得新观察并自动纠正，不得直接重放旧scope或坐标。输入、外部效果、登录和付款动作失败后不得自动重复，也不得切换 transport 重输。
- 只有设备/控制器/相机离线、设备独占失败、新观察不可用、目标完全不唯一或机械标定不可达时，才以明确运行故障记录 0 动作；不得用未公开的安全前提阻止任务，也不得以试探性点击换取信息。

## 工作树与结果口径

- 一个工作树只承担一个稳定、有限且可独立合并的职责。所有读取、编辑、测试和提交使用当前工作树绝对路径；硬件控制、阶段结论和最终集成由唯一主任务负责。
- 工作树交付必须说明本地提交、精确测试结果、修改边界和未完成边界，不得擅自推送。发现用户未提交修改时必须保留并避让，无法安全隔离时停止并说明冲突。
- 统一使用以下状态：`已实现`（代码存在）、`相关测试通过`（最小测试通过）、`完整回归通过`（全量自动测试通过）、`真机动作匹配`（真实画面上单个动作成功）、`阶段验收完成`（阶段所需全部真实证据成立且无剩余必做项）。
- `matched`、`blocked`、`succeeded` 按真实终态记录；动作匹配但最终 `blocked` 不能写成成功。0 动作只读结果、离线测试、Mock、历史截图和网页页面都不能替代要求动作的同会话真实设备证据。
- 规则文档、代码修改、测试通过或单次动作匹配不能自动推导阶段完成。仍有必需证据缺口时，只能说明核心能力和剩余缺口。
- 无法继续时只报告已证实事实、唯一阻塞、已排除原因和恢复条件；不以不相关修复掩盖阻塞，也不作没有证据的时间承诺。
- 当前阶段结论、会话 ID 和证据路径只记录在 `项目交接文档.md` 及当前验收台账，不写入本规则文件。
