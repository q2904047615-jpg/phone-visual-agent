# 动作后观察格式失败重试设计

## 背景

通用视觉 Agent 在一次已确认的机械臂动作后，必须重新观察真实画面并验证结果。当前页面观察器已经会对单次 Qwen JSON 格式错误进行一次格式修复请求；但若修复结果仍是残缺 JSON，动作适配器会立即终止整步。由此可能出现“机械臂动作和实际页面变化成功，但自动验证失败”的状态。

本设计只增强通用动作后观察链路，不增加任何 App 名称分支、固定坐标或专用流程。

## 目标

- 当动作后观察因可识别的 JSON 或协议格式错误失败时，允许重新采集实时画面并额外进行最多一次独立观察。
- 无论观察和验证尝试多少次，同一个确认请求最多执行一个物理动作。
- 第二次观察使用新的连续稳定画面，不复用可能过时的旧截图。
- 所有观察尝试的截图和错误原因均进入证据记录。

## 非目标

- 不自动补逗号、括号或猜测损坏 JSON 的语义。
- 不重试摄像头离线、画面不稳定、权限错误或其他非格式故障。
- 不扩大单次确认的权限范围。
- 不增加浏览器、微信、抖音或其他 App 的专用判断。

## 方案

### 重试位置

重试由 `GenericSingleActionAdapter` 的动作后观察循环管理。`GenericSceneObserver` 继续负责单次观察内部的紧凑格式修复；当它最终仍报告格式类错误时，适配器才使用剩余的一次动作后观察机会。

这样可以保持职责边界：观察器负责解释一组画面，适配器负责动作后重新采集、验证和“一次动作”约束。

### 数据流

1. 确认前重新观察并将动作绑定到当前可信元素。
2. 机械臂执行一个底层动作。
3. 采集第一组动作后稳定画面并调用观察器。
4. 若观察成功，按现有控制器规则验证页面变化。
5. 若观察最终失败且错误属于 JSON 或协议格式类，则保存错误和截图，重新采集第二组稳定画面并独立观察。
6. 第二次成功则正常验证；第二次仍失败则安全停止。
7. 任一分支均不得重新调用机械臂动作。

### 时间与次数边界

- 动作后独立观察最多两轮：原始一轮加一轮格式故障恢复。
- 每轮画面稳定采集使用独立的有限截止时间，避免第一次模型调用耗时吃掉第二轮画面采集预算。
- Qwen 提供方已有的单次请求超时保持不变。
- 非格式类观察错误不消耗第二轮模型调用。

### 错误与证据

- 第一轮格式错误不得被静默丢弃；最终失败信息需包含最后错误，并保留第一轮和第二轮截图路径。
- 成功恢复时，执行结果的证据列表同时包含两轮动作后截图。
- 物理动作计数在成功和失败情况下均保持为 `1`。

## 测试设计

1. 第一轮动作后观察返回格式错误，第二轮返回可信变化：执行成功，观察器被再次调用，机械臂只动作一次，两轮截图都被保存。
2. 两轮动作后观察都返回格式错误：安全失败，物理动作数为一，机械臂只动作一次，两轮证据都被保留。
3. 动作后观察返回非格式错误：立即失败，不进行额外观察，机械臂只动作一次。
4. 现有页面过渡状态重观察测试继续通过，确保验证失败重观察与格式失败重观察共享次数上限。
5. 运行通用动作适配器、页面观察器、通用编排器和网页接口相关回归测试。

## 验收标准

- 真实故障类型可以在不重复机械臂动作的前提下恢复。
- 无法恢复时保持安全停止，不接受损坏 JSON。
- 新代码不包含 App 名称、业务命令或固定坐标分支。
- 所有新增与相关回归测试通过。
