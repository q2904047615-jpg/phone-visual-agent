# 语义 IR 影子核心验收台账

> **历史影子批次，不是当前执行权威。** 当前正式协议和风险集合见 `用户决策与协议边界.md`；只有登录和付款需要确认。

## 1. 本批边界

本批只实现 `TaskSemanticIR` 的只读影子核心，不替换 DeepSeek v3 正式任务图，
不改变 Qwen、控制器、风险确认、服务或机械臂行为。影子结果必须永久携带：

- `authoritative=false`
- `execution_allowed=false`

任何影子编译失败都只能写诊断，不能放宽或阻塞现有正式执行链。

## 2. 当前唯一验收缺口与根因证据

必须证明同一任务可以稳定表达为类型化实体、状态变更效果和确定性风险策略，
并且约束文字不再创造风险。

当前真实失败样本：

- `poc/output/web/generic_supervised_20260818_175251_54e036d2/`
- 原目标：`打开微信，进入文件传输助手，输入“你好”，然后发送。`
- 旧合同把子目标约束 `确认发送对象为文件传输助手` 单独推成
  `unknown_external_effect`，再与正确的 `message_or_communication` 做并集，
  因此在 0 物理动作阶段拒绝任务图。

根因分类：通用语义合同缺陷。目标效果、身份约束、完成状态和证据要求使用
同一套自由文本风险扫描，字段角色没有进入本地裁决。

## 3. 同类失败与变化样本集合

样本位于 `poc/fixtures/semantic_ir/role_aware_risk_cases.json`，至少覆盖：

1. 发送目标 + `确认发送对象` 身份约束；
2. 相同发送效果的换 App、换收件人和换措辞版本；
3. 普通关注效果；
4. 付款效果；
5. 登录/身份认证效果；
6. 新类型但目标和预期结果明确的 `generic_effect`。

## 4. 已冻结的通用修复合同

### 4.1 类型化实体

实体使用通用列表，而不是固定五键：

- `entity_id`
- `entity_type`
- `role`
- `value`
- `source_span`
- `authority`

影子投影会保留现有实体，并区分用户逐字值与仅供规划的上下文值。

### 4.2 状态变更效果

所有会改变状态的任务都使用 `EffectIntent` 描述：

- 效果类型；
- 目标实体引用；
- 载荷实体引用；
- 来源子目标；
- 预期结果文字（本批仍为迁移诊断，后续由 VisualClaim 替换）。

`EffectIntent` 不包含坐标、机械动作和风险确认结论。

### 4.3 关键正确性绑定

本批只把效果目标和载荷绑定为关键约束。普通自然语言 constraints 不参与风险
分类；无法类型化的描述仍只供旧规划器使用，不得生成风险或执行权限。

### 4.4 本地风险策略

风险由本地配置根据 `EffectIntent.kind` 确定。默认需要确认：

- `authentication`
- `financial_transaction`
- `sensitive_permission_change`
- `irreversible_account_deletion`
- `irreversible_data_deletion`

发送、回复、关注、点赞、评论、发布、普通保存/修改、可恢复删除以及
`generic_effect` 默认自动。策略可以按 effect kind 覆盖，但任务执行中不得静默改变
配置版本。

### 4.5 影子权限边界

影子 IR 和风险决定只用于证据、测试和新旧结果比较：

- 不生成 confirmation scope；
- 不进入 Qwen prompt；
- 不进入控制器；
- 不授权物理动作；
- 不覆盖现有任务图风险字段。

## 5. 影响面、回滚与停止条件

影响面只允许包括：独立语义 IR 模块、影子编译入口、诊断证据和离线测试。
回滚时删除影子调用即可，旧正式链保持不变。

出现以下任一情况立即停止，不进入视觉/控制器批次：

- 影子结果影响现有任务图返回或异常类型；
- constraints 的措辞或位置改变风险决定；
- 普通发送/关注进入确认；
- 付款/登录被判为自动；
- 影子报告出现可执行权限；
- 相关回归或完整回归出现新增失败。

## 6. 验证清单

1. 当前真实发送失败 payload 的离线投影；
2. 全部字段角色变化样本；
3. 风险配置覆盖与配置版本固定；
4. 实体/效果/引用/重复 ID/额外权限字段反向测试；
5. DeepSeek planner 影子调用不改变旧返回和旧异常；
6. 相关任务图、编排和诊断测试；
7. 一次完整 Python 回归；
8. `git diff --check`。

## 7. 2026-08-18 实施结果

- 已实现独立 `TaskSemanticIR`、通用实体、`SurfaceRef`、`EffectIntent`、
  关键目标/载荷绑定、严格本地风险配置和非权威影子报告。
- DeepSeek 初始规划和重规划在正式校验前生成影子结果；影子异常被隔离，
  不改变旧任务图的返回、异常、风险门或执行权限。
- 当前发送失败样本的旧协议结果保持拒绝；同一份图的影子结果为
  `send_message -> automatic`，且 `recipient` 和 `input_text` 分别绑定。
- 三种约束措辞及约束在全局/子目标之间移动，均不改变语义摘要和风险决定。
- 付款、登录为 `confirmation_required`；普通关注、发送和明确的
  `generic_effect` 为 `automatic`。
- 影子失败诊断会保存脱敏影子报告，并固定
  `authoritative=false`、`execution_allowed=false`。

验证结果：

- 新影子核心与诊断：19/19 通过；
- DeepSeek 任务图与通用编排器：364/364 通过；
- 静态编译与 `git diff --check` 通过；
- 完整 Python discover：1398 项，30 项失败，未达到“完整回归通过”。
  30 项全部位于既有 `test_web_platform.ApiEndToEndTests`：一组仍期待已退役
  固定 App 兼容接口返回 200/201 而当前正式实现返回 410；另一组受到该旧套件
  遗留执行队列影响而返回 409。影子 IR 变更未修改这些路由、队列或硬件入口。

因此本批状态是：`已实现` + `相关测试通过`，不是 `完整回归通过`，也不代表
新协议已经接管正式执行。后续切换前需单独清理 Web 基线测试口径，但禁止为
通过旧测试而恢复固定 App 专用产品路径。
