# 通用视觉操作 Agent 架构约束

最高优先级产品目标见根目录 `项目最终目标.md`。本文只描述软件架构边界；与最终目标冲突时，以根目录文档为准。

本项目的最终产品是可扩展到多个 App、不同自然语言表达和多台手机的通用视觉操作 Agent，不是微信或抖音专用脚本集合。

## 唯一闭环

1. DeepSeek把用户原话整理为目标、高层子目标、约束、完成条件和风险，并可根据新状态调整剩余任务。
2. Qwen结合当前子目标，报告页面、可见语义元素、状态、位置和证据，并提出最多一个下一视觉动作及其预期结果。
3. 本地控制器校验目标唯一性、置信度、安全策略、坐标边界和一次一动作限制。
4. 动作适配器把已校验动作转换为一次机械臂底层动作。
5. 每次动作后必须重新观察并验证；结果不符时重新规划，目标满足时用可见证据结束。

## 不可退化的边界

- 不为每条新指令增加独立的线性工作流。
- 不允许模型绕过本地控制器直接执行裸坐标、系统命令或连续自由动作。
- 页面不稳定、目标不唯一、置信度不足或动作结果不明确属于运行故障；应先做允许的重新观察，仍无法执行时报告具体原因，不得把它们归为产品风险或据此新增长期边界。
- App 专用代码只能用于权限、账号行为和危险动作的安全策略，不能承担任务编排。
- 微信、抖音保留为兼容和验收场景；新增 App 不应要求修改通用场景协议或单步控制循环。
- 不得以某个单功能闭环的成功代替跨命令、跨App的通用能力验收。

## 通用动作

- `ensure_app`：确保目标 App 在前台。
- `observe`：重新观察页面。
- `tap_semantic`：按语义选择唯一控件并点击。
- `input_verified_text`：输入文字并逐段验证。
- `swipe`：按语义方向滑动。
- `back`：系统返回。
- `dismiss_overlay`：关闭阻塞弹层。
- `wait_for_change`：等待页面变化。
- `verify`：验证页面或元素状态。
- `finish`：只有完成条件有视觉证据时结束。

## 扩展原则

接入新 App 时，优先补充视觉样本、语义别名和安全策略。若必须修改任务编排核心或增加 App 名称分支，应先判定为架构问题并向用户反馈。

## 当前代码状态与迁移方向

- 现有监督式单步、稳定多帧观察、`element_id`、确认前重新观察和动作后验证继续保留，作为安全执行基础。
- DeepSeek从“只提出单步”迁移为“维护高层动态任务图”，但不能输出机械坐标或绕过控制器。
- Qwen从“只读场景”迁移为“目标驱动的场景观察＋单步视觉动作建议”，但不能直接调用机械臂。
- 普通导航和外部状态动作均允许在闭环中自动推进；只有登录/身份认证和付款/资金交易显示具体对象与内容并确认。
- 通用物理动作需要从点击、关闭弹层、滑动和返回扩展到长按、拖动以及经过验证的文字输入。
- 微信和抖音旧流程仅作兼容与回归素材，不再作为新功能主路径。
