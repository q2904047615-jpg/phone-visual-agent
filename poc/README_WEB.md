# 多 App 机械臂网页控制平台（第一版）

> 产品与架构最高优先级依据见根目录 `项目最终目标.md`。本文包含历史网页工作流说明；任何固定微信、抖音命令仅作兼容或回归素材，不得作为新功能主路径，也不得覆盖通用动态 Agent 目标。

## 日常启动

1. 打开卖家的“智联新途AI机械臂控制端”，确认摄像头画面正常。
2. 机械臂回到安全原点，手机打开到准备操作的页面。
3. 双击项目根目录的 `启动机械臂网页控制台.cmd`。
4. 浏览器会打开 `http://127.0.0.1:8765/`。
5. 选择微信或抖音，填写动作内容，创建任务草稿。
6. 核对确认框后，逐个确认执行。

紧急情况下先使用硬件急停。网页“停止任务”只会在当前最小动作结束后阻止后续动作。

## 当前支持

- 微信：按唯一完全匹配的聊天名称发送文字。
- 微信：按唯一完全匹配的聊天名称，从“最近”相册选择第1～20张图片并发送。
- 抖音：搜索关键词并验证视频结果页。
- 抖音：在当前推荐流或搜索结果中，批量点赞、评论或同时执行；每批目标1～10个，最多检查“目标数+5”页。
- 正式微信、抖音工作流使用“页面状态图 + 单一控制器”。`qwen3-vl-plus` 只报告当前页面状态、可见文字和控件中心，不得提出动作或计划。
- 用户确认的任务只保存目标参数，不再预先冻结线性步骤；控制器根据每轮新观察选择唯一动作，因此从聊天页、搜索页等中间页面启动时不会被旧计划游标卡住。
- 配置密钥后，所有自由文本均优先交给 `deepseek-v4-flash` 提取白名单任务参数；本地规则只在 DeepSeek 未配置时作为明确标注的降级入口。DeepSeek 调用失败时安全停止，不会换用另一套解析器重新解释。文本模型不掌握正式微信、抖音工作流的执行权。
- 中文输入由模型识别当前 QWERTY 的少量锚点，本地程序计算全部拼音键位并连续点击；模型只负责键盘确认、候选词选择和最终验收。
- 单次文字最长100字；中文最多4字一段，英文和数字最多20字一段，常用标点单独输入。
- 微信聊天名、微信正文、抖音搜索词和抖音评论共用同一输入恢复规则：每段后逐字验证完整输入框前缀；发现错字、漏字、多字或错误符号时，按实际全文字符数清空本次输入，确认空框后从第一段重打。每个输入框最多完整重输2次。
- 支持上划、下划、左划和右划。
- 每个视觉 Agent 任务生成独立 `report.json`，记录结果、步骤、耗时和截图证据。
- 未配置 DeepSeek 密钥时，本地规则 Agent 仍可识别常见固定表达；复杂表达会要求补充或配置密钥，不会转交视觉模型。
- 2–5 FPS 手机画面预览。
- SQLite 任务记录、执行截图和单任务串行队列。

## 配置千问视觉

1. 在阿里云百炼创建 API Key。
2. 双击项目根目录的 `配置千问视觉密钥.cmd`。
3. 在隐藏输入框中粘贴 `DASHSCOPE_API_KEY`，按回车。
4. 关闭旧的网页控制台，再双击 `启动机械臂网页控制台.cmd`。
5. 打开网页“设置”，确认“千问视觉 Agent”显示“已配置”。

密钥保存在 Windows 当前用户环境变量中，不写入项目文件、SQLite、
任务日志或网页。默认模型为 `qwen3-vl-plus`。如百炼账号使用不同地域
或专属工作空间，可另设 `DASHSCOPE_BASE_URL`。

## 配置 DeepSeek 文本理解

1. 在 DeepSeek 开放平台创建 API Key。
2. 双击项目根目录的 `配置DeepSeek文本理解密钥.cmd`。
3. 在隐藏输入框中粘贴 `DEEPSEEK_API_KEY`，按回车。
4. 关闭旧的网页控制台，再双击 `启动机械臂网页控制台.cmd`。
5. 打开 `/api/device`，确认 `intent_agent.configured` 为 `true`。

密钥只保存在 Windows 当前用户环境变量中。默认使用非思考模式的
`deepseek-v4-flash`，仅将自然语言提取成白名单任务 JSON；Qwen3-VL-Plus
继续只负责摄像头页面观察。可通过 `DEEPSEEK_INTENT_MODEL` 显式切换到
`deepseek-v4-pro`，但日常命令解析通常没有必要。

正式工作流每个动作都执行以下闭环：

1. 在至少 1.5 秒内采集 4 帧。
2. 千问只返回页面状态、文字、控件中心和置信度；返回中出现动作或计划字段会被拒绝。
3. 单一控制器根据状态图和用户确认目标选择唯一动作。
4. 本地执行一个最小动作。
5. 重新观察页面；未知、低置信度或风险页面立即停止并留存截图。

## 通用任务编排预览（开发中，默认不执行）

新的上层编排边界已经建立为：

`DeepSeek 结构化意图 → GoalSpec 目标约束 → 语义动作计划`

- `GoalSpec` 明确记录 App、来源操作、目标参数、成功条件和安全上限。
- 语义动作只描述“观察页面、验证控件、执行单个动作、复核结果”等能力，不包含原始坐标、Shell 命令或卖家控制端命令。
- 抖音批量任务只有在 `record_verified_result` 记录一次已验证成功后才增加完成数；达到目标数后不会再无条件上划。
- `POST /api/agent/plan-preview` 只返回意图、GoalSpec 和计划预览，不创建 SQLite 任务、不进入执行队列，也不会操作机械臂。
- 默认队列编排模式仍为 `legacy`；通用编排器不会自动连续运行。已另行开放人工监督单步会话，每次明确确认最多处理一个节点。

### 单步语义执行器与假观察循环

`semantic_executor.py` 提供尚未接入实机的第二阶段离线能力：

- 执行器保存计划游标和计数器，每次只能返回一个 `SemanticAction`。
- 动作适配器必须交回同一节点的动作结果和一份新页面观察，执行器才会继续。
- 页面晃动、置信度低于0.72、动作结果错位或语义证据不足时立即失败。
- `record_verified_result` 只有在红心、评论发送等目标证据成立时才增加计数。
- `finish` 只有在目标计数、微信聊天标题和已发送内容等成功条件成立时才完成。
- `ScriptedFakeEnvironment` 和 `OfflineSemanticLoop` 使用确定性的假页面测试分支、循环与安全停止，不连接摄像头、千问、卖家控制端或机械臂。

完整循环执行器目前没有注册为自动网页任务入口，也不会被
`ROBOT_ORCHESTRATOR_MODE` 自动启用。首页的“开始人工监督单步”使用以下安全边界：

- 启动时只调用 DeepSeek 结构化意图并采集一次真实观察，机械臂动作数为0。
- 每点一次“确认执行这一步”，最多处理当前一个语义节点，然后再次暂停。
- `record_verified_result` 和 `finish` 只更新本地控制器，不碰手机。
- 实机动作和只读观察统一经过 `SemanticActionRouter`；当前只允许
  `observe`、`ensure_app` 和单次 `tap_semantic:heart`。
- 其他点击、滑动、输入、发送会停在原节点，不调用摄像头或机械臂。
- 如果动作已经落笔但动作后复核失败，报告会记录已发生的物理动作数，并禁止自动补点。

对应接口：

- `POST /api/agent/supervised/start`：创建暂停会话，只观察。
- `GET /api/agent/supervised/{session_id}`：读取会话和待执行节点。
- `POST /api/agent/supervised/{session_id}/step`：要求 `confirmed=true`，最多执行一个节点。
- `POST /api/agent/supervised/{session_id}/cancel`：取消会话。

把这些单步动作连成无人值守自动循环属于后续独立阶段。

### 动态 QWERTY 拼音键盘

`type_pinyin` 不再只依赖一套固定键盘坐标。千问在每次输入或清空前只识别
`Q/P、A/L、Z/M、退格` 七个锚点，本地程序校验三行 QWERTY 的顺序、键距、
行距和退格键位置，再确定性计算其余字母中心。

- 支持尺寸或位置发生变化的完整标准 QWERTY 拼音键盘。
- 九宫格、手写、悬浮键盘、锚点被遮挡或几何校验失败时立即停止。
- 字母点击仍由本地代码完成，不为每个字母重复调用视觉模型。
- 候选词选择、输入框验证和发送继续保持为相互分离的动作。

## 标定与模板

抖音点赞沿用原有 `templates/douyin_home.png` 和视觉识别。

微信工作流使用运行时视觉识别，在每次执行时动态搜索并验证：

- 手机桌面的“微信”文字；
- 微信搜索结果中唯一完全匹配的目标聊天；
- 目标聊天顶部的实际标题；
- 输入完成后出现的“发送”文字。

微信流程不需要预先采集图片模板。输入框只会在目标聊天标题已通过
OCR 验证后，按照微信底部输入区的页面结构定位。

抖音评论仍需从当前卖家控制端画面采集以下模板，放到 `templates/web/`：

- `douyin_comment_button.png`
- `douyin_comment_input.png`
- `douyin_comment_send.png`

缺少模板时，网页会显示“待标定”并拒绝执行该工作流；系统不会猜坐标。

微信文字输入还需要：

1. 安装卖家目录中的 `卡饭输入法_0.4.6.apk`。
2. 将 `lbduanyu.txt` 复制到手机并批量导入自定义短语。
3. 关闭“五码自动上屏”。
4. 在 `config.exe` 中标定卡饭输入法键盘像素区域。
5. 人工验证卖家控制端“输入”按钮能输入中文、字母和数字。

第一版文字不支持表情、换行和生僻符号；图片仅支持手机“最近”相册前20张中的单张选择，不支持电脑文件直传。

## 安全边界

- 服务只监听 `127.0.0.1`。
- 所有会改变 App 数据的操作都必须逐次确认。
- 自然语言入口只能映射为四种结构化状态图任务，不生成线性计划、坐标或系统命令。
- 微信发送和抖音互动只使用用户确认的目标参数；单个任务不能跨 App。
- 网页和模型均不提供系统命令或 Shell 接口。
- 模型只能使用点击、输入已确认 ASCII、拼音输入已确认中文、清空错误文字、四方向滑动、主页、返回、
  等待、结束、停止。
- 视觉坐标必须在 0～1000 范围；置信度低于 0.72 时拒绝执行。
- 视觉 Agent 单任务最多 15 个动作，未确认完成则自动停止。
- 控制端/摄像头离线、页面未知、页面变化或模板不稳定时停止。
- 直播、广告弹窗及未知页面不会点赞、评论或滑动。
- 点赞和评论支持单次或用户明确指定数量的连续任务；每个任务最多10个成功目标，
  每页仍需视觉确认，直播、广告、风险弹窗和未知页面不会执行互动。
- 自动关注仍不提供。

## 模拟模式

双击 `启动网页控制台_模拟模式.cmd` 可在不连接机械臂的情况下体验页面和任务队列。模拟模式不会产生任何实机动作。

## 数据位置

- SQLite：`poc/output/web/tasks.sqlite3`
- 工作流截图：`poc/output/web/`
- 原有 PoC 日志和截图：`poc/output/`

视觉 Agent 的每次运行目录中还会保存 `report.json`：

- 普通操作成功：`outcome=completed`
- 测试任务通过：`outcome=passed`
- 低置信度、未知页面或执行异常：`outcome=failed`

页面状态图的新运行报告还包含 `reliability_metrics`，用于区分：

- 动作已经发出但画面未确认；
- 控件定位失败；
- 机械执行异常；
- 未知页或阻塞弹层触发恢复；
- 完成条件验证失败。

汇总受监督连续运行数据：

```powershell
poc\.venv\Scripts\python.exe poc\analyze_state_graph_reliability.py `
  --root poc\output\web `
  --output poc\output\web\state_graph_reliability_summary.json
```

历史报告会计入“未带指标的旧运行”，但不会混入新版本成功率。只有包含
`reliability_metrics` 的新报告才参与动作确认率、恢复确认率和失败阶段统计。
